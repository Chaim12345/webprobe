# Dynamic DOM checks

Fourteen DOM families share one instrumented Chromium visit per URL in a scan run, each reported in the plain (DOM-based), reflected (reflected DOM-based) or stored (stored DOM-based) variant, attributed per hit: a hit holding the token submitted in an earlier request is the stored variant, a hit holding the query token present in script text of the exact navigation response fulfilled to Chromium is the reflected variant, anything else is the plain variant. Only GET history entries with HTML baselines containing a script tag, inline event handler or javascript: URL are visited. Inert HTML is skipped. A fresh standalone scan or outer batch clears the cache, and crawl runs get a new cache by construction. No process-global result cache is used.

Chromium use is bounded per run: at most 2 concurrent browsers and 100 navigations (DOM_MAX_CONCURRENT_BROWSERS / DOM_MAX_PROBES_PER_RUN in webprobe-support). Over budget the DOM checks fail closed: no browser is launched and no hits are reported. Each admitted operation sends at most 64 same-origin GET/HEAD requests total, including the outer stored-token submission and every intercepted browser request. Baseline is outside this operation. A simple page needs three requests including baseline; there is no reflected re-request. Admission includes budget, browser slot, successful startup and DevTools setup before submission; cancellation or an unknown submission outcome stops further traffic without retry.

All intercepted HTTP requests use the scanner transport, including its configured upstream route, cookie jar, session rules and pause handling. Only exact same-origin GET/HEAD requests are allowed. Recorded Cookie/Authorization headers are supplied when the browser has not already supplied them. Responses are normalized before delivery to Chromium, with a 4 MiB body cap and a 32 KiB response-header cap. No arbitrary POSTs, form submissions or off-origin requests are forwarded.

Nothing leaves Chromium's own network stack: on top of Fetch interception, the browser's proxy is a closed loopback port, so traffic that bypasses interception (speculative preconnect/prefetch, background services) has no route out. Workers and off-origin frames/connections are restricted by an added CSP. Service workers are bypassed; WebSocket URLs are blocked, non-proxied WebRTC UDP is disabled, DNS prefetch and hyperlink pings are off. These restrictions can change application behavior and miss findings. Chromium is launched with a fresh temporary profile, not the user's browser profile, and it is removed when the probe ends. Only hits on the exact probed origin are retained.

The instrumentation records a canary reaching a wrapped sink, with two distinct run-owned tokens per navigation: one in the query string and one in the fragment. A hit's source is attributed by which token the recorded evidence contains (location.hash, location.search, both, unknown when a single-token probe cannot attribute, or stored when the evidence holds the token submitted in an earlier request; never guessed). The burp.Zwf8 confidence mapping is established for the location.hash source only; search, mixed and unknown provenance are reported as Tentative. Recorded values are capped (50 hits per page, 300 chars per value). This establishes data flow, not necessarily an exploitable breakout. JavaScript wrappers are not engine hooks: eval becomes indirect/global, popups are swallowed with a stub handle, and Location's non-configurable setters are not covered. Storage, cookie and document-domain setters can mutate the temporary browser profile, which is discarded. Existing page JS may make GET requests with application effects, as in any active scan.

Requires an available Chromium binary. The family labs, the source-provenance matrix lab, the reflected- and stored-variant labs and the cache-refresh lab have been exercised with an actual browser; broader application compatibility is not established.

Coverage boundary: docs/specs/R-13-dom-coverage-matrix.md lists the proved source/sink/family cells and the known gaps. Fourteen wrapped families is not blanket DOM analysis.

Variant labels describe token observations, not proven storage mechanisms or JavaScript string-literal origins. Response/sink co-occurrence does not prove the sink read that response text. Both variants are Tentative. Failed/unknown outcomes are logged and cached for this run, not treated as successful clean probes.
