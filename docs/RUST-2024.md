## Temporary destruction audit

The migration warning locations were read before formatting changed their line numbers:

- net engine and collaborator listener accepts, upstream connects, and the Intruder baseline/test listeners move successful sockets into an owner. Earlier destruction of the emptied Result cannot close the moved socket.
- Intruder transformations, sitemap comparison and WebSocket rule matching move owned strings/regex results into the selected branch. No mutex guard or callback is transferred by the emptied Result.
- body spill returns an Arc-owned segment. Project saver removes an owned job from the queue while the state guard remains statement scoped; callback execution remains after that guard's scope.
- project settings and snapshot struct updates retain owned clones. Dropping an extra clone earlier does not invalidate retained data. Repeater WebSocket detail uses the retained history collection.
- scan-library current clones the config under its guard before returning the tuple. Earlier guard release is acceptable and avoids holding it during later atomic reads. Settings import applies owned settings, not a borrowed guard.
- SMTP/guestbook fixtures retain successful sockets in bindings and render owned responses before writes. Comment-list guards are statement scoped. Collaborator polling moves the request outcome into its binding; timeout still awaits the same in-flight request before progressing, with no new request started by a dropped temporary.

These are targeted ownership and lock-scope checks, not a proof of every possible destructor interleaving. Existing protocol/persistence and polling tests supply regression coverage.
