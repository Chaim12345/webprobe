# Rust 2024 migration (L10, issue #40)

The desktop app, core, support and report crates inherit edition 2024 and MSRV 1.95 from `[workspace.package]`. The vendored MCP client was already on 2024. No dependency versions or lockfile entries changed. The workspace root's edition also selects Cargo resolver 3. CI checks all workspace targets/features on both 1.95.0 and stable, with separate caches.

## Compatibility changes

- Rename local `gen` bindings to `generation`; keep rand 0.8 calls as `r#gen()`.
- Keep the existing `unit!` macro matching rules with `expr_2021` fragments.
- Preserve return-position lifetime capture with `use<'a>` in codec header iteration and `use<>` in the renderer test helper.
- Preserve the screenshot panic-result match and the scanner action branch's scope where cargo fix identified changed if-let temporary lifetimes.
- Mark renderer environment mutation unsafe and call it as the first operation in main, before panic/signal setup, workers or GL/window libraries. The pure renderer policy tests never mutate the environment.
- Apply edition-enabled clippy let-chain suggestions and MSRV clippy boolean simplifications. Short-circuit conditions and operation order remain unchanged. Cache two regexes in the characterisation test server for the 1.95 regex-in-loops lint.
- Apply Rust 2024 style formatting in a separate commit.

## Temporary destruction audit

`cargo fix --edition --workspace --all-targets` also reported tail-expression drop-order warnings that have no automatic fix. Reviewed cases:

- Listener accepts (net engine and collaborator) and upstream connects move successful sockets into bindings, workers or the return value. The temporary is then an empty Result, not a second socket owner.
- Regex construction (intruder, sitemap comparison and WebSocket rules) moves the regex into a binding; no lock or callback cleanup depends on the emptied Result's destruction.
- Body spill and the project saver move the segment/job out of an Option/Result. Segment storage is Arc-owned. The match temporary cannot release a live mutex guard or invoke a job callback before the selected branch uses it.
- Project settings clone/merge, WebSocket history detail and settings installation retain independent owned values/Arc clones. Dropping an extra clone earlier does not invalidate the retained data or change a save callback's timing.
- Headless engine selection moves the selected engine into the match binding; crawl items remain owned by their destination collection. The scan-config lock is released at its preceding statement, not held across browser work.
- The SMTP/guestbook test helpers move successful sockets and use statement-scoped mutex guards. Responses are built before the selected page is sent.

These sites adopt 2024 tail-temporary cleanup without manual lifetime extensions. No protocol, persistence format, scan policy or request ordering change is intended. Real browser/process/network behavior remains covered by the existing test suite, but tests do not prove equivalence for every possible drop ordering.

## Existing unsafe code

Reviewed the three pre-existing unsafe blocks. The body-store slice still depends on append-only segment ranges and its owning Arc; project mmap still depends on atomic rename rather than in-place writes; screenshot GL calls still run inside the painter callback with the supplied current context and owned pixel buffer. Their operations are unchanged, with no new references to mutable statics. The project's mmap assumption about other processes not modifying the inode is pre-existing, not made stronger by this migration. The new unsafe environment calls are the only added unsafe operations, with the explicit startup-only contract above.
