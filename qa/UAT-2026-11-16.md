## Defects, ranked

1. **Intruder results overlay is input-dead** — cannot close, cannot select a row; blocks the app until restart. Severity: high (data loss / forced restart). Repro: run any attack, then click ✕, a row, or press Escape.
2. **Repeater Cancel does nothing** — in-flight request completes; the button only reflects state. Severity: high (users believe a slow/blocked request was stopped).
3. **Comparer has one shared item collection** — item 1 and item 2 lists always show the same entries, so a real A/B diff is impossible from the UI; Paste is also inert. Severity: high (tool cannot do its job).
4. **HTTP history is not persisted** — restarting loses all captured traffic. Severity: high for a Burp clone.
5. **Window intermittently starts unmapped** (~50 % of launches) while the proxy binds — looks like a hang; requires external `windowmap`. Severity: medium.
6. **Paste into message editors unreliable/ignored** — blocks the normal "copy request from chat/notes" workflow. Severity: medium.
7. **Time column truncated to `08:39:`** and the table needs horizontal scrolling at 1440 px; message panes show only ~4 lines. Severity: low/medium (readability).
8. **Menu bar minimal** (Search/Settings/Quit only). Severity: low (parity gap).

## Automation / MCP findings

- WebProbe was built with `eframe` `default-features = false` and **without `accesskit`**, so it never joined the AT-SPI bus. That rules out both `agent-desktop` and `egui-mcp` element paths on the stock build.
- A separate worktree `/root/webprobe-a11y` (branch `a11y-accesskit`) adds the `accesskit` feature and calls `cc.egui_ctx.enable_accesskit()`; it builds and runs. After activation the app appears on the a11y bus (agent-desktop reports an accessibility frame owned by the app PID) but the frame is not associated with the X window, so `agent-desktop` refuses it (`native_window_unproven`) and `egui-mcp`'s `get_ui_tree`/`find_by_*` return zero elements.
- `egui-mcp-server 0.0.5` is installed (`/root/.cargo/bin/egui-mcp-server`) and registered in `~/.config/opencode/opencode.json` as `egui-mcp` (`DISPLAY=:94`, `EGUI_MCP_APP_NAME=WebProbe`). `ping` → `pong`. `check_connection` fails because `egui-mcp-client` (IPC socket for screenshots/coordinate input) requires **egui 0.33**, while this tree is on 0.29.
- Trial upgrade to egui/eframe 0.33 plus `egui-mcp-client 0.0.5` is running in `/root/webprobe-egui33` (branch `egui33-trial`) with build output in `/root/webprobe-egui33/build.log`.
