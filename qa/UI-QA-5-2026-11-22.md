# UI QA second pass, 2026-11-22 (team/ui-qa-5-first-run-save)

Method: debug build under Xvfb 1440x900 with `qa/qa.sh`, tour of all 13 tabs, then real traffic (curl through the proxy to a local fixture at 127.0.0.1:8099), row selection and the history context menu. Compared by eye with Burp Community's layout. Tested on the tip of `team/ui-qa-b-20261122` (includes #87, #90, #93 fixes).

## Fixed here

- **First run: autosave fails with "No such file or directory".** On a machine without `~/.local/share/webprobe` every save attempt shows a red toast ("Save failed: cannot create project temporary file ...") and nothing is saved. `project::save` now creates the missing parent directory. Test: `save_creates_missing_parent_directory`.

## Also fixed (follow-up commit)

- Empty tables (Comparer lists, Sequencer, Extensions) drew a full-height vertical scrollbar thumb; the bar now shows only when rows exist.
- Status bar claimed `Proxy 127.0.0.1:PORT . intercept off` even when the bind failed. It now reads "not listening" in the warning colour.
- History numbering gaps: scan issues, held intercept items and WebSocket frames now have their own counters (`next_issue_id`, `next_queue_id`, `next_ws_id`), so Proxy history numbers are contiguous. Project restore recounts each list from its own rows, so old files (one shared counter) load correctly. Test: `issue_ids_do_not_consume_history_numbers`.

## Not changed, on purpose

- Crawler items still share the history counter. The Target site map merges history and crawl rows and selects by id, so a separate crawl counter would make two rows share one id. Needs a keyed selection change first.
- The wide black bar under an empty HTTP history is the table's horizontal scrollbar: the default columns are about 6% wider than a 1440 px window. Not an empty-state bug.

## Crawl counter (follow-up PR, team/crawl-own-ids)

Crawler and extension site-map items now number from `next_crawl_id`. The Target site map keys its selected row by `(is_crawl, id)` (`find_site_entry`), so a history row and a crawl row with the same number never select each other. Project restore recounts history and crawl lists separately; old files with one shared counter load unchanged (test `old_shared_counter_project_loads_with_per_list_counters`).
